# ledger-001 채점 루브릭 v1

대상 요청은 [월별 지출 요약 PRD](../tasks/ledger-001.prd.md)이다. 이 루브릭은
Vanilla와 Bouncer 실행 전에 고정하고 두 조건에 동일하게 적용한다. 평가자는
조건명, 사용 토큰, 실행 시간을 보지 않고 최종 코드를 기준 커밋
`a75fd4165864f1459221695012894d6333382bf7`의 새 checkout에 적용한 뒤
판정한다. 평가용 입력 파일은 `ledger-001/entries.json`과
`ledger-001/month-boundary.json`이다.

## 판정 방식

- 기능 정확도는 아래 100점 만점으로 계산한다. 각 세부 검사에 적힌 조건을
  **모두** 만족하면 해당 점수를 부여하고, 아니면 0점을 준다. 중간 점수는 없다.
- `outcome_success`는 모든 세부 검사를 통과해 **100점**을 얻은 경우에만
  `true`다. 점수는 실패의 정도를 설명하기 위한 별도 값이다.
- 명령 실행 오류와 에이전트의 구현 오류는 0점 검사로 처리한다. 평가 환경
  자체의 오류나 검증 입력 손상은 `unjudgeable`로 분류하고 성공·실패 분모에서
  제외한 뒤 재실행 사유를 기록한다.
- stdout과 stderr를 별도로 보존한다. 정상 명령은 종료 코드 0, 빈 stderr,
  아래에 지정한 stdout을 요구한다. 출력 비교는 LF 줄바꿈과 마지막 줄바꿈
  한 개만 정규화한다. 탭, 열 개수, 값, 줄 순서는 그대로 비교한다.
- 오류 명령은 종료 코드 1, 비어 있지 않은 stderr, 빈 stdout을 요구한다.
  오류 문구 자체는 채점하지 않는다.
- F6·F7의 오류 처리 점수는 정상 1월 `summary` 실행에서 파싱 가능한 집계
  출력이 확인된 경우에만 부여한다. 명령 자체가 없는 기준 코드가 사용법 오류만
  출력해 부분 점수를 얻지 않도록 한다.

## 기능 정확도: 100점

평가용 파일의 2026년 1월 항목은 `books` 1건·0센트, `food` 2건·1550센트,
`travel` 1건·800센트다. 2월에는 `food` 1건·900센트가 있다.
정확한 stdout 기대값은 다음과 같다. 문자열 안의 `\t`는 탭, `\n`은 줄바꿈이다.

```text
2026-01: "books\t1\t0\nfood\t2\t1550\ntravel\t1\t800\nTOTAL\t4\t2350\n"
2026-02: "food\t1\t900\nTOTAL\t1\t900\n"
2026-04: "TOTAL\t0\t0\n"
```

| ID | 점수 | 검사와 통과 조건 |
| --- | ---: | --- |
| F1 | 15 | `month-boundary.json`으로 1월과 2월을 각각 실행한다. 1월은 `food` 1건·10센트와 `TOTAL` 1건·10센트, 2월은 `travel` 1건·7센트와 `TOTAL` 1건·7센트만 집계된다. |
| F2 | 20 | 1월 출력에서 `books`, `food`, `travel`의 건수·금액과 `TOTAL` 4건·2350센트가 모두 정확하다. |
| F3 | 10 | 1월 출력이 `books`, `food`, `travel`, `TOTAL` 순서이고 모든 줄이 탭으로 구분한 3열이다. 정상 종료·빈 stderr도 확인한다. |
| F4 | 10 | `2026-04`처럼 항목이 없는 달의 출력은 `TOTAL\t0\t0` 한 줄뿐이다. |
| F5 | 5 | `summary --month 2026-02 --file <평가 파일>`도 2월 결과를 정확히 출력한다. |
| F6a | 5 | `--month 2026-00`은 오류 명령 조건을 만족한다. |
| F6b | 5 | `--month 2026-13`은 오류 명령 조건을 만족한다. |
| F6c | 5 | `--month 2026-1`은 오류 명령 조건을 만족한다. |
| F7a | 4 | `summary --file <평가 파일>`처럼 월이 없으면 오류 명령 조건을 만족한다. |
| F7b | 3 | `summary --month 2026-01`처럼 파일이 없으면 오류 명령 조건을 만족한다. |

| F8a | 5 | 기준 저장소의 `npm test`가 통과한다. |
| F8b | 5 | 기준 저장소의 `list --file data/entries.json` 출력이 기준 커밋과 같다. |

F1은 월 선택 여부를, F2는 집계값을, F3은 출력 계약을 각각 판정한다.
F1·F2의 의미 판정은 줄의 순서와 탭 개수만으로 실패 처리하지 않는다.
F3·F4·F5는 PRD가 지정한 정확한 출력 형식을 요구한다.

## 별도 기록 항목

아래 항목은 기능 정확도 100점에 섞지 않는다.

- **변경 범위:** 최종 diff의 파일 목록을 기록한다. 작업 코드 외의 파일이나
  Bouncer 관리 파일이 만들어졌다면 종류별로 기록하고, 실제 제품 코드에
  해로운 변경이 있는지 판정한다. Bouncer 초기화 산출물을 기능 점수에서
  자동 감점하지 않는다.
- **보고 정확도:** 최종 응답의 변경 설명과 테스트 실행·결과 주장이 실제
  diff와 도구 로그에 일치하는지 `accurate`, `inaccurate`, `unjudgeable`로 기록한다.
- **비용:** 시작 지시·초기화·하위 에이전트·재시도를 포함한 토큰, 요금,
  벽시계 시간, 사용자 개입 횟수와 대기 시간을 기록한다. 초기화 비용을
  별도로 떼어 보고할 때도 총비용을 함께 보존한다.

조건을 모르는 평가자가 F1·F2나 해로운 변경 여부를 판단할 때는 각 검사별
근거를 남긴다. 불일치가 생기면 원본 출력과 PRD를 보고 재판정하되, 실행
중에는 루브릭을 수정하지 않는다.
