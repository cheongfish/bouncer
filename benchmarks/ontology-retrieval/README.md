# ontology-retrieval

컨텍스트 문서에서 결정적으로 만든 온톨로지 색인이 "과거 결정 질의"에 답하는 비용을 grep보다 줄이는지 재는 실험이다.
배경과 설계는 [`../co-change-impact/ontology-retrieval-plan.md`](../co-change-impact/ontology-retrieval-plan.md)에 있다.
포트폴리오용 독립 실험이며 플러그인 코어에는 넣지 않는다.

```text
benchmarks/ontology-retrieval/
  README.md
  common.py          문서·git 읽기 공용 함수
  build_index.py     문서 본문 → index.json (생성물, git 무시)
  make_gold.py       git 이력 → questions.json (질문과 정답, 고정)
  query.py           색인 질의 CLI (조건 B)
  eval_static.py     에이전트 없이 색인 질의와 grep을 정답에 대어 봄
  questions.json     질문 50개와 정답 (seed 0, develop 711be703)
  static.json        정적 평가 질문별 결과
  static.txt         정적 평가 요약
  noise_evidence.py  엔티티 정답 쌍별 diff 근거 수집
  noise_evidence.json, noise_labels.json  근거와 사람 분류(83쌍)
```

## 출처 분리 원칙

| | 출처 | 쓰지 않는 것 |
| --- | --- | --- |
| 색인 | 컨텍스트 문서 본문(백틱 토큰, 게이트 코드 패턴) | git 이력, frontmatter `task_commits` |
| 정답 | task 커밋 diff와 변경 파일(`task_commits`로 BP에 연결) | 문서 본문 |

문서가 말하는 것으로 코드가 실제로 한 것을 맞히는지 잰다. 정답을 Contract 텍스트에서 뽑으면 색인이 당연히 이기므로 그렇게 하지 않는다.

## 실행

저장소 루트에서 실행한다. Python 3 표준 라이브러리와 `git`, `grep`만 쓴다.

```bash
D=benchmarks/ontology-retrieval
python3 -I $D/build_index.py . $D/index.json
python3 -I $D/make_gold.py . $D/questions.json          # 약 45초. 질문 세트를 바꿀 때만
python3 -I $D/eval_static.py . $D/index.json $D/questions.json $D/static.json
python3 -I $D/query.py $D/index.json entity worker-model
```

## 질문

- universe: `task_commits`로 커밋에 연결되고 소스 외 파일 변경이 있는 BP 75개. 그 밖의 BP 예측은 맞는지 알 수 없어 채점에서 빼고 따로 센다.
- 엔티티 30개: HEAD의 `scripts/src`에서 뽑은 후보 중 정답 BP가 1~10개인 것.
  - 게이트 코드(G/S) 10개
  - kebab-case 문자열 리터럴(거절 사유·kind 등) 10개
  - export 심볼 10개
  - 정답은 task 커밋 diff의 +/- 줄에 그 토큰이 단어로 나오는 BP다.
- 파일 20개: 정답 BP가 2~10개인 변경 파일. 정답은 task 커밋이 그 파일을 바꾼 BP다.

## 정적 평가 결과 (2026-10-15, 사전 점검)

조건 정의:
- Q: `query.py` 결과
- Gw: `grep -rlw -F`. 출력량은 같은 패턴의 `grep -rn` 바이트로 잰다.
- Gs: 파일 이름 stem으로 grep

| 범위 | 조건 | P | R | F1 | 출력 중앙값(B) |
| --- | --- | --- | --- | --- | --- |
| 전체 50 | Q | 0.54 | 0.51 | **0.50** | **407** |
| | Gw | 0.52 | 0.53 | 0.50 | 3,914 |
| 엔티티 30 | Q | 0.40 | 0.30 | 0.33 | 255 |
| | Gw | 0.39 | 0.30 | 0.32 | 2,072 |
| 파일 20 | Q | 0.76 | 0.83 | 0.77 | 755 |
| | Gw | 0.72 | 0.87 | 0.76 | 14,776 |

- Q − Gw F1: 전체 +0.005, 95% CI [−0.025, +0.032]. 정확도는 같은 수준이다.
- 출력량은 Q가 중앙값 기준 약 10배(엔티티 8배, 파일 20배) 작다. 에이전트 실험에서 입증할 토큰 감소의 근거다.
- 종류별 F1(Q / Gw):
  - kebab 코드: 0.58 / 0.57
  - 게이트 코드: 0.32 / 0.31
  - 심볼: 0.08 / 0.08
- 심볼은 두 방법 모두 거의 못 찾는다. 문서가 내부 함수 이름을 기록하지 않기 때문이다. 문서 기반 검색의 한계이고 색인 문제가 아니다.
- 엔티티 재현율이 0.30에 그친다. 커밋이 바꾼 엔티티의 상당수를 문서가 언급하지 않는다는 뜻이다.

사전 점검 중 조정 한 가지: 처음 색인은 백틱 토큰만 썼다. 게이트 코드가 `G8·G14`나 `` `S15`–`S17` ``처럼 쓰여 F1이 0.12(grep 0.31)였다.
게이트 코드는 고정 패턴이 있으므로 본문 전체에서 뽑고 범위를 펼치도록 보강했다. 이 조정 뒤 색인 규칙과 질문 세트는 고정한다.

## 정답 노이즈 분류 (2026-10-15)

엔티티 질문의 (엔티티, 정답 BP) 83쌍 전부를 diff 근거로 사람이 분류했다.
근거 수집은 `noise_evidence.py`(→ `noise_evidence.json`), 분류와 이유는 `noise_labels.json`에 있다.

| 라벨 | 뜻 | 쌍 | 색인 재현율 | grep 재현율 |
| --- | --- | --- | --- | --- |
| I | BP 목적상 엔티티를 도입·변경·검증 | 31 (37%) | 68% | 68% |
| A | 판단 불명 | 2 | 50% | 100% |
| R | 리팩터: 테스트 이름 형식(095/002) 13, 모듈 타입 정비(061/003) 6, 테스트 정리(092/002) 4, 공백·이동 2 | 25 (30%) | 4% | 4% |
| T | 테스트 준비 코드에서 헬퍼로만 사용 | 8 (10%) | 0% | 0% |
| M | 다른 목적의 줄 수정에 함께 포함(표 행, 문장 재배치, import 목록, 주석) | 17 (20%) | 29% | 29% |

- 정답 쌍의 60%(R+T+M 50쌍)가 부수적 변경이다. 엔티티 재현율 0.30의 대부분은 문서 한계가 아니라 정답 노이즈였다.
- 의도적 쌍(I)만 보면 문서 기반 재현율은 68%다. 색인과 grep이 같은 쌍을 찾는다.
- 종류별 의도적 쌍 재현율(색인): 게이트 코드 8/10, kebab 코드 11/13, 심볼 2/8.
  심볼은 노이즈를 걷어내도 낮다. 문서가 내부 함수 이름을 기록하지 않는다는 해석은 유지된다.
- 의도적 정답만으로 다시 채점하면(의도적 쌍이 있는 엔티티 질문 19개):
  - 색인 P 0.53 / R 0.64 / F1 0.56
  - grep P 0.51 / R 0.64 / F1 0.55
  - 원래 정답 기준 F1 0.33 / 0.32에서 올라간다.
- 엔티티 질문 30개 중 11개는 의도적 쌍이 하나도 없다. 예: S11·S10·S3은 095/002의 테스트 이름 변경만 정답이다.

정답 생성 규칙의 결함이다. 에이전트 실험 전에 정답 규칙을 고쳐야 한다(아래 "다음 단계").
이 수정은 색인 성능이 아니라 사람 라벨과의 일치도를 기준으로 하므로, 색인에 유리하게 맞추는 것이 아니다.

## 정적 평가의 한계

- 출력 바이트는 토큰 대리 지표다. 에이전트는 `grep -l` 뒤 파일을 열거나, 색인 결과를 grep으로 다시 확인할 수 있다.
  실제 감소는 에이전트 실험으로만 입증된다.
- 정답은 "diff에 토큰이 나온 BP"다. 테스트 픽스처처럼 부수적으로 나온 경우도 정답에 들어간다.
- universe 밖 예측(질문당 4~6개)은 채점하지 않았다. `task_commits`가 없는 오래된 BP들이다.

## 다음 단계

정답 규칙 v2 (에이전트 실험 전):
- 짝지은 -/+ 줄이 엔티티 주변을 빼고 같으면 제외(R: 이름 형식·공백·이동)
- 엔티티가 테스트 파일에만 나오고 BP가 그 엔티티의 소스·규칙을 바꾸지 않으면 제외(T, 일부 R)
- 위 규칙의 결과를 `noise_labels.json`과 대조해 일치도(정밀도·재현율)를 보고한 뒤 고정
- M(부수 언급)은 자동으로 거르기 어렵다. 남는 노이즈로 보고한다

에이전트 실험:
- 조건 A: grep·파일 읽기만 / 조건 B: `query.py`와 필요하면 grep
- 질문 50개 × 조건 2 × 3회 = 300회 실행
- 질의당 토큰, 도구 호출 수, 답의 P/R을 기록한다
- 사전 등록 가설: B가 재현율을 0.05 넘게 잃지 않으면서 질의당 토큰을 30% 이상 줄인다
- 보고 시 전체 세션 기준 환산(과거 문서 검색 몫 약 4%)을 함께 적는다
