# 벤치마크 태스크 정본

한 회차에 쓰는 태스크는 이 디렉터리의 JSON 열 개가 전부다. `.benchmarks/` 아래 산출물은 회차 로그일 뿐 정본이 아니다.

## 파일

이름은 `<id>.json`이다. `id`는 kebab-case이고 파일 이름과 같아야 한다.

각 파일은 다음 키를 모두 갖는다.

| 키 | 내용 |
| --- | --- |
| `id` | 태스크 식별자. 브랜치 이름이 아니다. |
| `base` | 고정 커밋. `git rev-parse --short HEAD`가 내는 짧은 sha. |
| `prompt` | 두 arm에 그대로 넘기는 지시. 판정 문장을 넣지 않는다. |
| `done_when` | 심사자만 보는 완료 조건 배열. |
| `checks` | 이 저장소에서 실제로 돌아가는 명령 맵. |

`base`에 빈 문자열이나 `develop` 같은 브랜치 이름을 넣으면 재현이 깨진다.

## 한 회차, 하나의 `base`

열 태스크의 `base`는 같은 값이다. 태스크마다 sha를 바꾸면 arm 비교가 태스크 비교와 섞인다.

이 파일들을 처음 쓸 때 넣은 `base`는 작성 시점 worktree의 `HEAD` 짧은 sha다. 그때의 `develop` 계열 커밋에는 이후 태스크가 붙일 usage 계측 플래그가 아직 없다. 그 sha로 회차를 돌리면 토큰을 기록하지 못한다. 작성 시점 값이 최종값이 아닌 이유다.

## 실행 회차가 `base`를 일괄 갱신한다

회차를 열 때 운영자는 그 회차의 공통 커밋 짧은 sha를 정한 뒤, 이 디렉터리 JSON 열 개의 `base`를 그 값으로 한꺼번에 고친다. 파일 하나만 고치지 않는다. 계측 플래그가 들어 있는 커밋으로 옮기는 갱신도 이 규약을 탄다.
